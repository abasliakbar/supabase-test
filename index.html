Set up the bank table policies

Run this in the Supabase SQL Editor. It enables RLS and lets authenticated users access only rows whose user_id matches their session.

alter table public.bank enable row level security;

drop policy if exists "Users can view own balance" on public.bank;
drop policy if exists "Users can update own balance" on public.bank;
drop policy if exists "Users can insert own row" on public.bank;

create policy "Users can view own balance"
on public.bank for select
using (auth.uid() = user_id);

create policy "Users can update own balance"
on public.bank for update
using (auth.uid() = user_id)
with check (auth.uid() = user_id);

create policy "Users can insert own row"
on public.bank for insert
with check (auth.uid() = user_id);

If you already created any of these policies, drop the existing policy of the same name before creating it again.

Understand the security boundary

To test RLS, sign in as one account and remove the .eq("user_id", user.id) filter from the select in this page. You should still only receive your own row: the browser filter is convenient, but the database policy is the security boundary.

The anon key is meant to be used by browser apps; RLS is what limits its database access. Never put a service_role key in this page: it bypasses RLS.

The session is persisted by Supabase Auth in this browser. For a stronger guarantee of one bank row per account, also enforce a unique constraint on bank.user_id in the database.
